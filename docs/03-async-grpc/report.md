## Q3.1

网络应用与普通本地程序相比，除了业务逻辑，还必须处理连接建立、序列化、网络延迟、请求失败、服务端状态以及客户端和服务端的版本兼容。本地方法调用通常能立即得到结果，而网络调用需要异步等待，并且成功发送不等于对方一定成功处理。程序还要区分参数错误、资源不存在、当前状态不允许操作和服务器内部错误，并保证单个错误请求不会使常驻服务退出。

本次实现中额外的复杂点主要有：

1. 内部 C# 类型与 Protobuf 类型需要逐字段、双向转换；
2. 大文件结果不能一次返回，需要使用服务器流；
3. RemoteCli 要在等待网络时保持异步调用方式；
4. Agent 是有状态单例，需要正确反映当前目录和分析状态；
5. 网络层异常和业务状态码必须分别处理。

## Q3.2.b（使用 AI）

本次作业使用了 AI 辅助。提示词的核心内容是：阅读 proto、项目框架和官方测试，补全类型转换、AgentSession、AgentService 和异步 RemoteCli，并检查错误状态与流式返回顺序。AI 主要用于生成初始代码、检查 gRPC 接口用法和梳理异常映射。

验证过程中曾发现一个错误：Protobuf 的可选字符串属性不能直接赋值为 `null`，否则会使成功结果在转换 header 时抛出异常。根据失败测试定位后，改为只在确有错误信息时设置该字段。这个过程加深了我对 Protobuf 生成代码和流式响应调试的理解。
